### P3 · Command plane (4 weeks)

- [~] FSM with transition table, critical store, dedicated writer, recovery at start. Done (`powermug-command`): the writer thread (`writer`) owns the command journal; every transition is one transaction, never batched with telemetry; clients on any thread wait for their answer. On this host, a submission and a transition take p50 0.41 ms and p99 0.68 ms (500 pairs; the NFR-PERF-003 budget of 20 ms p99 is for the qualification hardware). the states of [GW] 11.3 as an enum, and the transition table; a test checks every pair of states, that terminal states are absorbing, and that every state is reachable. The critical journal (`commands`, `command_transitions`, `idempotency`, in critical.db, WAL, synchronous=FULL): idempotent submission (a known `command_id` returns its state, PM-CMD-003), checked transitions, intent written before a network call and its result after (PM-CMD-002), and the restart rules of 9.7 and [GW] 11.5 (an execution sent without confirmation or an intent left open is IN_DOUBT and never replayed; a ready command is emitted only if its TTL, revision, owner epoch and active HA role pass; a revision or epoch change fails it). 15 tests. Reading choices, to confirm with the owner: the exact edges of the table are read from the diagram, with `Ready` and `SelectConfirmed` allowed to go to IN_DOUBT at restart; a `RECEIVED` or `VALIDATED` command interrupted at restart goes to FAILED; a selection that cannot be attributed to the new session goes to IN_DOUBT. Not done: the dedicated writer thread (the journal is synchronous today), and the link to the North and South adapters. The fault injection between states at process level is done for the journal (`tests/fault.rs`); not yet across the cell's dispatch path.
- [~] Authorization per issuer, point, operation, value and mode; maintenance mode. Done (`powermug-command::authorization`): an explicit ACL per commandable point (a grant per issuer, its operations and a value rule: any, boolean, or range); `authorize` checks the mode first (maintenance and shadow refuse every command as REJECTED_UNAVAILABLE), then the point, the issuer, the operation and the value (REJECTED_AUTH). `Acl::missing` lists the commandable points without a grant (PMV-ACL-001). 6 tests, including a refusal recorded as a terminal state in the journal. Reading choices, to confirm: the maintenance refusal uses REJECTED_UNAVAILABLE (the spec gives no code for it); a value outside the granted range is REJECTED_AUTH, since the range is part of the authorization of 9.3. Identity levels (GW 11.6, `powermug-command::identity`): each North protocol's identity has a granularity; a grant states its finest-required level, and a coarser identity is refused; the journal records the identity and its level. Not done: the identity is not yet carried from the North adapter to the core, the API that sets the mode and audits it, and the ACL check in the revision validator.
- [~] IEC 104 single, double, set-point commands, direct and select-before-operate. Done (`powermug-adapter-iec104::command`): the adapter sends a single command (select or execute) and reads the station's answer (activation confirmed, terminated, or refused). Verified end to end against a real `igs-iec104` station on loopback: select, confirmation, execution, termination, and a refusal reaching the controlling side. Known limit, in `igs-iec104`: the station refuses an execution that has no prior selection, so a direct execute (S/E = 0) is refused by the library; this needs a change in that library, to be raised with its owner. Also done: double commands (select and execute, verified against the station), and the expiry check just before emission (`send_before_expiry`, PM-CMD-004: an expired command is never sent, verified). Also done: float set points (C_SE_NC_1), normalized (C_SE_NA_1) and scaled (C_SE_NB_1) set points, select and execute, verified against the station with the values it accepted; a normalized value the format cannot carry is refused before anything is sent. Also done: regulating steps (C_RC_NA_1), select and execute, verified against the station. The contract carries commands (`ExecuteCommands`) and the adapter's dispatch loop is written (`powermug-adapter-iec104::dispatch`): it refuses a dispatch of another owner epoch (not sent), reports an expired command (never sent), emits the others to the station, and reports the station's answers (confirmed, terminated, refused). Verified in one process: core, contract socket, adapter loop and a real station. Core side: `powermug_cell::commands::Dispatcher` journals a submission, authorizes it, admits it under the partition's owner, dispatches it with its owner epoch and expiry through the emission guard, follows the adapter's answers (confirmed, terminated, refused, not sent, expired), and puts an unanswered command IN_DOUBT when the stream ends. Seven tests with a fake adapter. Also fixed: a point with one grant per operation of the same issuer refused the second operation (authorization now selects the grant that names the operation). The dispatcher is wired into the cell's South instances: each session has a command link (dispatcher and route); the supervisor attaches the route for each cycle of the adapter's command stream, applies its updates, and at cycle end detaches it and puts the unanswered commands IN_DOUBT. The server of each instance is the commanded one. Today every command is refused: the dispatcher has the empty ACL and no owner. The blocker of the adapter binary is lifted: `run()` (the path the binary uses) opens the command stream, sends the dispatches through the redundancy group, and reports the station's answers; a dispatch arriving with no connection started is reported not sent. Verified against a real station through `run()`. The activation epoch is now taken from the partition's confirmed owner at each start of an adapter (`Dispatcher::activation_epoch`, 0 without a confirmed owner). A takeover during a cycle now restarts the instance: the cell checks the activation epoch every 200 ms, and a change is a planned restart (`Supervisor::restart_now`), which neither delays the next start nor uses the restart budget. Verified: a takeover replaces the process. North entry point: `POST /commands` over mTLS hands a command to the cell's gateway, which routes it to the dispatcher of its point (`powermug_mgmt::CommandGateway`, implemented by `powermug_cell::commands::Gateway`). The command rules are in the cell configuration (`commands.acl`, validated: point, operations, values, identity level). The issuer is the common name of the mTLS client certificate, at client granularity; a certificate without a common name is refused, and an execution is refused to any identity other than the one that submitted the command. Only direct and select operations are accepted by `POST /commands`; the execution that follows a selection is `POST /commands/{id}/execute` (body: the point), which runs the dispatcher's execution of a selected and confirmed command: 404 for an unknown command, 409 when it cannot be executed now (not selected and confirmed, or already finished). The actor of `POST /mode` is the certificate's common name too: a body `actor` is optional and must equal it (`actor_mismatch`, 400). The dispatcher can block a session for a `COMMAND_CRITICAL` change and classify its open emissions (`block`, `unblock`), but no activation calls it yet: the change class is not computed. Still open before a command can be enabled: the rules of a real site. Not done: that binary wiring, the North entry point that submits commands, and the group of redundancy.
- [~] Dispatch with partition epochs. Done (`powermug-command::ownership`, `::dispatch`): each partition has an owner (confirmed at an epoch, in cession, in shadow, or unowned) and an epoch that increases at every takeover. At submission, a partition without a confirmed owner refuses the command as REJECTED_UNAVAILABLE, and an expired command as REJECTED_INVALID. The South side holds the epoch of its activation: a dispatch with another epoch fails, and a command past its expiry is never sent (PM-CMD-004, PM-CMD-005). 5 tests, including a takeover that refuses the old epoch. Not done: the South adapter's use of the guard (the adapter does not receive the epoch yet), and the link with the cell's revision registry.
- [~] Hash-chained audit records. Done (`powermug-command::audit`): one record per command write (submission, transition, intent, result, restart decision), in the same transaction; each record carries the SHA-256 of the previous one. `verify_audit` checks the chain and reports the first altered record; `audit_head` gives the hash to anchor outside the store. 5 tests: an altered record is found at its position; a removed last record is visible only against an anchored head. Export and standalone verification done: `audit::verify_export` checks an export against an anchored head (five tests). Not done: the transport of the export to a separate domain, the periodic anchoring in the cell, and the audit of local actions (mode changes are already in the chain).
