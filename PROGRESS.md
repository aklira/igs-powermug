### P2 · IEC 104 telemetry loop (5 weeks) · milestone M1

Status at 2026-11-20: every item that can be built and tested in this repository is written. The phase is **not exited**: the exit needs the bench, the gridloop driver, and the target API with mTLS, which are not written (see "Not done").

- [x] `iec104-client` adapter on `igs-iec104` (`powermug-adapter-iec104`): controlling station on `igs-iec104` 0.1.0 (crates.io, no TLS); connects, starts the data transfer, interrogates the station, converts the monitoring ASDUs, sends them to the core over `StreamEvents`; a lost connection is reported as a lost session (`ReportCommunication`) and its return as a restored one. Mapping by common address and object address; quality read back from IEC 104 (IV, NT, SB, BL, OV); unmapped objects counted. Tests: 6 on decoded ASDUs, 2 end to end against a real `igs-iec104` station on loopback (values reach the lane with their quality; station loss reaches the lane as a lost session).
- [ ] `iec104-server` adapter (controlled station serving SCADA from the image, with the redundancy group). Not written. Needs a decision on its scope (see the summary of the phase).
- [x] Partition lanes, ingestion, process image (`powermug-core`): point table with one site per lane; a batch is checked, journaled in one transaction, then applied to the image (PM-TEL-001); class C bypasses the journal.
- [x] Adapter stream: `RECEIVED`, then `DURABLE` only after the commit, or `REJECTED` with the reason; a class C batch is acknowledged `RECEIVED` only (`Durability::NotJournaled`).
- [x] Cycle supervision (§7.8): deadlines in a 100 ms wheel; stale events committed with the batch that reveals them; expiries undone if the commit fails. 12 tests on a simulated clock, 4 in the lane.
- [x] Communication loss and restoration (§7.6, PM-TEL-007): one `CommunicationState` and one invalid quality event per valued point; points suspended; degradation kept until a fresh value. Q11 records the quality and class choices. The 2 s budget is not measured.
- [x] Telemetry log (`powermug-store`): WAL, `synchronous=FULL`, one transaction per batch, class C refused, duplicate event ids refuse the batch; point column nullable for session events. 11 tests.
- [x] Single writer (`powermug-store::writer`): one thread for the cell, batches grouped for up to 5 ms or 4,096 events, one savepoint per batch so that a refused batch does not take its group; reads through the same thread. Tests with several threads and with a duplicate in the group. The lanes share it through the `Journal` trait.
- [x] Snapshots and recovery (§7.2, FUN-IMG-004): the image is snapshotted, and `Lane::open` restores the newest snapshot and replays only the journal after it; a snapshot is taken every 60 s when `snapshot_if_due` is called. Five tests on recovery, four on snapshots.
- [x] Image rebuilt at start (PM-TEL-003): every replayed point is degraded and suspended until a fresh value; class C is not recovered; a record that does not replay stops the recovery.
- [ ] Destination views (the image as seen through a destination's route chain). Not written; no route chains exist yet.
- [ ] Cursors and retention in the telemetry log. Not written.
- [x] Critical store generation pointer (`powermug-store::generation`): prepare idempotent per revision id; activation in one transaction, refused when the parent is no longer active (PM-CFG-003); rollback to the previous revision, idempotent per revision (PM-CFG-004 to 006). 8 tests. Its file is separate from the telemetry log (PM-TEL-006).
- [ ] Validation stages 2 to 4 for the P2 subset. Not written: the typed partition revision model (only the stage 1 envelope check exists in `powermug-revision`), so the semantic checks, the capability checks and the cell checks cannot be written yet. Change classes (HOT, SESSION_RESTART) need the same model.
- [ ] Target API v1 (`/capabilities`, `/state`, `/revisions/*`, `/indicators`) with mTLS. Not written. mTLS needs a decision on the TLS backend and on the certificate management (see the summary of the phase).
- [ ] Containerfile, Quadlet template, bench profile. Not written.
- [ ] gridloop: `powermug.py` driver for S3 and `powermug@1` in `capabilities.json`. Not done: it lives in another repository, and changing it needs the owner's approval.
- [ ] `powermug-bench` and the first p99 gate in CI. Not written: the gate needs the CI runner and the qualification hardware (decision 2).
